# 专利核心思想学习笔记

> 依据专利技术交底书《一种主要面向大学毕业生的求职批量投递系统及方法》+ 系统设计文档整理。
> 目的：认真学习专利的**设计意图**与**数学自洽性**，不矮化、不简化，逐条沉淀可复用的方法论。

---

## 一、系统到底在解决什么（五大目标）

专利并不把「求职投递」当做一个简单的"自动发简历工具"，而是抽象为**对求职场景中已普遍存在的数据对象（用户信息 / 岗位信息 / 投递任务 / 投递反馈）的顺序化、可核验处理方法**。五大目标：

1. **多来源岗位信息统一字段处理** —— 不同平台字段名不一致，先统一到一个字段数据库，再做后续计算；
2. **任务级关联** —— 目标岗位 ↔ 针对性简历 ↔ 投递入口 ↔ 投递状态，对应关系**持续维持**（不是一次性生成）；
3. **生成式 AI 输出受「字段表约束 + 短任务切分 + 核对回写」**，系统性抑制 AI 幻觉（这是本专利最具一般性的贡献，可迁移到任何"让 LLM 只填白名单字段"的场景）；
4. **投递结果集中回写与跟踪**；
5. **画像依据投递反馈做数学上可验证的动态修正**（不是黑盒推荐，而是有公式、可验证）。

## 二、六层架构（分层解耦，每层输出是下一层输入）

```
① 用户输入层   L0身份骨架 / L1经历盘点 / L2经历深挖 / L3求职偏好，核检
② 模型层1画像  硬约束构造 + 经历向量化 + 用户表示(式一)
③ 操作层1匹配  短任务采集岗位 + 硬约束过滤 + 打分排序(式二式三)
④ 操作层2建任务 目标岗位 → 投递任务表（一岗一条）
⑤ 模型层2执行  按岗分配经历(式四) + 受限简历生成
⑥ 结果输出层   批量投递 + 结果回写 + 语义回归修正(式五)
     └────────────── 统一字段数据库 ──────────────┘
```

**关键设计**：把"模型层"（画像、生成）和"操作层"（匹配、建任务）分开，模型层产出**数学对象**（向量、权重、分数），操作层产出**数据对象**（任务表、岗位表）。这样每一步都可独立验证。

## 三、统一字段数据库：专利灵魂（两个基本属性）

> 字段数据库是**多维数组形式的统计表格**，用户编号列作一个维度，用户各项信息的字符串逐一作为独立维度。

1. **字段名全局唯一** —— 每对象以统一字段名存取，各步骤以字段名为核对基准；
2. **字段值可核对** —— 写入记录须经「字段名 + 取值规则」双重核对，不合法不写入。

**学习要点**：这是"核对回写"的根基。AI 生成的内容只有字段名命中白名单（`RESUME_ALLOWED_FIELDS` / `RESUME_ALLOWED_L2`）才会被采纳，其余丢弃——用**结构约束**而非"提示词祈祷"来抑制幻觉。

## 四、五个数学公式（数学自洽，可验证）

| 公式 | 含义 | 关键数学性质 |
|---|---|---|
| 式一 | 用户表示 u = Σ α_k·v_k | 凸组合：α_k≥0 且 Σα=1，u 恒在经历向量凸包内 |
| 式二 | 余弦 s = (u·j)/(‖u‖‖j‖) | 相似度 ∈ [-1,1] |
| 式三 | p = σ(w_s·s + w_δ·δ)，δ=cos(j,c_+)−cos(j,c_-) | 逻辑斯谛映射 p∈(0,1)；δ 只在正负中心都形成后启用 |
| 式四 | γ_k = α_k·e^{τ·b_k} / Σ α_m·e^{τ·b_m} | 指数倾斜，输出仍在概率单纯形上（非负和为1） |
| 式五 | α_k ← α_k·e^{η·z·I_k} 再归一化 | 乘性更新；z=0 或 I 全0 时恒等 |

**学习要点**：
- 式一/式四/式五都刻意保证输出在**概率单纯形**上（非负、和为1），这是"数学可验证"的具体落地；
- 式三的 δ 是**冷启动→反馈**的分界点：无历史样本时 δ=0，系统退化为纯余弦排序；有反馈后才引入"更靠近进面试岗位中心者加分"。这就是"越用越准"的数学来源；
- 式五的 `I_k`（写入指示）把"这条经历有没有真的写进某岗的简历"纳入权重更新，防止"没参与投递的经历"被误判。

## 五、七步流程 + 第八步「再画像」（闭环）

七步：采集核检 → 画像 → 匹配 → 建任务 → 分配经历+生成简历 → 投递 → 回写修正。
第八步（专利强调的闭环）：用修正后的权重 + 岗位中心**重新匹配**，让式三的 δ 真正生效。

**学习要点**：不是"投完就结束"，而是"投递反馈回流 → 修正画像 → 再匹配"，形成数据闭环。这呼应了目标 5（画像动态修正）。

## 六、AI 幻觉抑制（保护点 1，最值得学）

三个手段叠加，缺一不可：
1. **字段表约束**：只允许 LLM 填写字段表中已有的字段（白名单）；
2. **短任务切分**：不整段自由成文，而是"为某岗填写字段表"这一短任务；
3. **核对回写**：字段名与字段表不一致就丢弃。

**学习要点**：这套"约束 + 短任务 + 核对"是通用的 LLM 工程范式，比"写更长的提示词"可靠得多。

## 七、我学到的三条可迁移方法论

1. **用结构约束替代提示词祈祷**：字段白名单 + 核对回写，比 prompt 里"不要编造"有效；
2. **让每个数学对象落在已知集合上**：权重/分配在概率单纯形、分数在 (0,1)，性质可断言、可回归测试；
3. **冷启动与反馈两段式**：无数据时给一个确定性的退化结果（纯余弦），有数据后再叠加修正项（δ），避免冷启动时"假装有中心"。

### 7.2 数学细节补充（认真推导，非表面理解）

**式三 δ 的几何意义**：δ = cos(j, c_+) − cos(j, c_-)，其中 c_+ 是「进面试岗位」向量的均值、c_- 是「未进面试岗位」向量的均值。δ 的本质是「这个岗位在语义空间里更靠近进面试那类、还是未进面试那类」——δ>0 说明它长得像「被认可」的岗位，匹配分被抬高；δ<0 则被压低。冷启动时两类中心都为空，δ 强行置 0，系统诚实地退化为纯余弦排序，不假装有先验。

**PCA 降维（SVD）原理**：岗位/用户向量是 128 维，无法直接可视化。PCA 用「中心化 → 奇异值分解 → 取前两个主方向」把数据投影到方差最大的二维平面。投影后点的**相对距离近似保留**（高维语义近的，二维上通常也近），所以散点图上「★（你的画像）离哪个岗位近」≈「哪个岗位更匹配」。

**凸组合的几何意义**：u = Σα_k v_k 且 α_k≥0、Σα=1，意味着用户表示 u 落在各经历向量 v_k 张成的**凸包**内——即「你的画像必然是你经历的某种加权平均，不会凭空跳到经历之外」。这既是数学约束，也防止画像被 AI 或异常数据「带飞」。
