# 设计：用户池 × 岗位池统一匹配空间（对齐 · 聚类 · 自由选维）

> 2026-11-24 立项。核心诉求：**把云端的每一个用户画像和共享岗位池画进同一个空间，
> 让"人和岗位的远近"在图上直接可见，并能按簇聚类。**

---

## 1. 核心概念

两个池子，一个坐标系：

- **用户池**：全队发布到云端的画像快照（式一 `user_vec`，语义向量）。
- **岗位池**：全队抓取去重汇聚到云端的岗位（`jobs.embedding`，同一词表嵌入）。
- **对齐**：用户向量和岗位向量由**同一份统一字段词表**生成（式一 `u = Σ w_k·e_k`
  与岗位嵌入共用词向量 `e_k`），因此天然生活在同一语义空间——余弦距离就是匹配分（式二）。
- **聚类**：对岗位点做 KMeans 成簇，一簇 = 一个方向的工作（如"后端工程簇""数据分析簇"）；
  用户点按最近簇归属着色，一眼看出"这个人落在哪个岗位簇的引力范围内"。
- **自由选维**：两条通道——
  1. **语义空间**（主成分投影，PCA 对用户+岗位**联合矩阵**拟合，两端共用同一投影基）；
  2. **画像轴空间**（`viz.USER_AXES` 已支持的统计轴，用户侧；岗位侧映射同义指标后同图）。

## 2. 数学保证（不需要新公式）

| 环节 | 复用什么 |
|---|---|
| 用户向量 | 式一凸组合 `user_vec`（feedback 闭环已持续更新） |
| 岗位向量 | `jobs.embedding`（检索入库时已算） |
| 匹配距离 | 式二余弦相似度 |
| 投影对齐 | PCA 对联合矩阵 `[用户向量; 岗位向量]` 一次性拟合，分别投影——**这是"对齐"的关键**：分开拟合的两张 PCA 图坐标不可比，联合拟合才可比 |
| 聚类 | KMeans；K 用轮廓系数（silhouette）在 2~8 内自动选，或手调 |
| 簇命名 | 簇内岗位描述词的词频 Top3，自动标注 |

## 3. 数据架构

### 3.1 云端表（均为现有表，只补用法）

| 表 | 角色 | 现状 |
|---|---|---|
| `profile_pool` | 用户池：`user_vec`/`weights`/`pos_center`/`neg_center`/`delivered_count`/`interview_count` + `owner`/`visibility` | 列已齐；**写入通道断链**（见 3.2） |
| `jobs` | 岗位池：`fields`/`embedding`/`owner` | 已通（cloud_sync 双向同步） |

### 3.2 发布通道（本轮要修的核心缺口）

**现状断链**：`mydata.publish_snapshot(owner, user_id)` 整体 `@_cloud`，从**云端**
`profile_pool` 按 `user_id` 读快照再复制——但本地优先改造后快照只写**本地**，
云端按本地 user_id 永远查不到，`publish_snapshot` 实际不可用。

**修复设计**（新增，不破坏旧函数）：

```
mydata.push_profile(owner)
  ├─ 读【本地】profile_pool 最新快照（feedback 式五每次闭环都在写）
  ├─ 读【本地】user_records 最新 l0（取姓名/学校/专业，仅作图上标签）
  └─ 写【云端】profile_pool：visibility='public'，owner=账号名
     （同一 owner 只保留最新一条 public：先删后插，保持一人一点）
```

配套：
- `mydata.retract_profile(owner)`：撤回（DELETE 自己 owner 的 public 行）。
- 桌面端「画像对比」页加**「发布我的画像到云端 / 撤回」**按钮。
- 每次反馈闭环后桌面端提示可重新发布（快照是幂等覆盖，重复发布无害）。

### 3.3 隐私边界（写死）

- 默认**不发布**；发布动作由用户显式点击。
- 上云的只有向量、权重、统计计数、标签名（姓名/学校/专业）——**不上传简历原文、
  联系方式、经历明细**。
- 可一键撤回；撤回后他人空间图立即少一个点。

## 4. 模块设计

### 4.1 数据层 `mydata.py`

| 函数 | 职责 |
|---|---|
| `push_profile(owner)` | 本地快照 → 云端 public（一人一点，先删后插） |
| `retract_profile(owner)` | 撤回公开画像 |
| `list_space_users()` | 云端全部 public 画像（owner、user_vec、标签、统计） |
| `list_space_jobs(limit=2000)` | 云端岗位池（embedding + 关键字段） |

### 4.2 计算层 `unispace.py`（新模块，纯函数可测）

| 函数 | 职责 |
|---|---|
| `joint_pca(user_vecs, job_embs, dims=3)` | 联合矩阵 PCA，返回两端同基投影 + 各主成分载荷 Top 技能词 |
| `cluster_jobs(job_embs, k_range=2..8)` | KMeans + silhouette 自动选 K，返回簇标签 + 簇关键词 |
| `nearest_cluster(user_coord, centers)` | 用户点归属最近岗位簇 |
| `build_space(users, jobs, dims)` | 总装：对齐 → 聚类 → 归属 → DataFrame（含"对齐度"= 用户与最近簇心的余弦） |

### 4.3 可视化 `viz.py`

- `unified_space_chart(df, dims=3, highlight_owner=None)`：Plotly 3D/2D。
  岗位点按簇着色（一簇一色，中心大点 + 簇名标注）；
  用户点统一星形金色，当前用户放大加光环；
  坐标轴标题 = 「主成分 1（载荷 Top：Java、Spring…）」，让不看数学的人也知道轴是什么。
- 网页画像广场新增模式开关：**「只看用户池 / 用户+岗位统一空间」**。

### 4.4 展示层

- **网页** `pages/01_画像广场.py`：加统一空间模式（数据来自云端，任何人看到同一幅图）。
- **桌面端**「画像对比」页：按钮「发布画像 / 撤回 / 生成统一空间图」，
  图用浏览器打开（现有 build_compare_chart 同款方式）。

## 5. 端到端流程

```
队友A：投递闭环 → 式五更新本地画像 → 点「发布画像」→ 云端用户池 +1
队友B：抓取岗位  → cloud_sync.push → 云端岗位池 +N
任何人：打开画像广场 → 选「统一空间」→ unispace.build_space(云用户, 云岗位)
        → 联合 PCA 对齐 + KMeans 聚类 → Plotly 交互图
        → 看到：某用户落在「后端工程簇」边缘、离「数据分析簇」最远 → 投递建议可视化
```

## 8. 规模边界（诚实声明）

- 千级用户 + 万级岗位：本方案全量现算无压力（PCA/KMeans 都是毫秒级）。
- 超过十万级：需要预聚合（簇心缓存、分层抽样渲染），那是商业平台的问题，现在不做。
- 对齐的质量上限取决于 embedding 质量：哈希兜底模式下"远近"是词表共现近似；
  接真实嵌入模型（已有接口）后空间语义更准。图上不放精确匹配分，只放相对位置。
